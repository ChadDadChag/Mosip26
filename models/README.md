## Conversion checks

- **MiniFASNet.** The networks are built from the unmodified upstream `MiniFASNet.py` with
  `conv6_kernel=(5,5)`, `num_classes=3` and `embedding_size=128`. Weights are loaded with
  `strict=True` after stripping the `module.` prefix.
  - torch vs onnxruntime 1.31.0 on 20 random 0..255 inputs: max logit difference 2.6e-6 (V2) and
    2.9e-6 (V1SE). The pass limit is 1e-3.
  - Cross-check against yakhyo/face-anti-spoofing's release ONNX exports: max softmax[1] difference
    1.2e-7 for both models.
  - The export is byte-reproducible with torch 2.14.1.
- **Face mesh.** TFLite interpreter (TF 2.15.1) vs onnxruntime 1.31.0 on 3 random inputs and on 2
  face crops built by the reference pipeline: max landmark difference 1.5e-4 (limit 0.01) and max
  flag-logit difference 2.7e-5 (limit 1e-3).
  - tf2onnx is **not** byte-reproducible: re-running it renames the folded constants
    (`const_fold_opt__N`), although the graph and the weight bytes are identical.
  - The committed file is therefore the canonical one. Its SHA-256 is recorded in the golden
    fixtures and, from Phase 4, in the signed manifest.
- **YuNet** is used exactly as published.

## Reproduce

Run from the repo root, using the two Python 3.11 venvs described in `tools/requirements*.txt`.

```
python -I models/tools/fetch_models.py --extras            # main env: download + verify sources, install YuNet
python -I models/tools/export_minifasnet.py --yakhyo       # main env: .pth -> ONNX + parity
python -I models/tools/make_golden.py                      # main env: golden fixtures (needs all 4 models)
python -I models/tools/convert_facemesh.py inputs          # main env: mesh check inputs (needs golden images)
python -I models/tools/convert_facemesh.py convert         # tf2onnx env: tflite -> ONNX + TFLite reference outputs
python -I models/tools/convert_facemesh.py verify          # main env: ONNX vs TFLite
python -I models/tools/inspect_models.py                   # main env: regenerate tools/model-io.md
python -I models/tools/sanity_webcam.py                    # main env, with a person at the camera
```

Downloads go to `models/tools/.cache/`, which is gitignored. A converted mesh will differ in
bytes from the committed one (see above), so after re-converting, check it with `verify` and do
not commit it unless the model itself changed.

## The Python reference pipeline is the specification

`tools/reference_pipeline.py` defines every pre- and post-processing step that the Java analyzer
must reproduce: resampling, letterbox, YuNet decoding and NMS, the mesh ROI and back-projection,
head pose, the Silent-Face crop and the score fusion. Each formula is in the docstring of its
function.

`tools/make_golden.py` runs it on two public-domain images and writes the expected values to
`liveness-analyzer/src/test/resources/golden/`. Those values include per-stage tensor statistics,
so a parity failure in Java can be traced to one stage.

## Integrity

From Phase 4, a signed `manifest.json` / `manifest.sig` in this directory covers these files.
The analyzer refuses to load a model whose size or SHA-256 differs from the manifest.
